# Design note

Key design choices. The agent is the shipped cascaded voice receptionist (gpt-oss-120b), evaluated as text through the same prompt, tools and booking backend it uses on calls. Its five tools enforce their own rules in code, because a prompt rule is only a request. Booking needs the caller's latest turn to name exactly one offered option. A booking claims its slot atomically and carries a request ID, so a lost response is reconciled from a receipt instead of rebooking. Emergency routing locks out further scheduling, and offers are cleared when the department or a patient detail changes. Wording the model reads after a tool call lives in a versioned policy file, the only surface the automatic improver may edit. Simulated patients are deterministic scripts, not a second LLM, so a score change reflects the agent, not the simulator.

Evaluation. There are 16 development scenarios and 4 held-out ones, covering corrections, refusals, ambiguous consent, department changes, taken slots, outages, a booking that commits but loses its response, an emergency, prompt injection, past dates, and out-of-scope requests. Code checks what code can: database rows, duplicates, tool order. A Claude judge grades only consent, truthfulness, recovery and clarity, and must cite event IDs. Critical failures (wrong or duplicate booking, a made-up handoff or callback, an emergency breach) fail a trial regardless of score. The judge's main blind spot showed up in calibration: it passed "connecting you to the Emergency ward" because the tool output told the agent to say it, and a transcript can't reveal that no transfer system exists. It now gets a ground-truth sheet of what each tool really does.

Improvement loop. The full suite runs, and failed trials are grouped by their most frequent critical failure. Claude Opus receives the traces and returns a structured proposal: root cause, exact before/after text, expected effects and regression risks. The CLI rejects proposals that cite evidence not in the traces or edit anything outside the policy file. The candidate reruns the whole suite, and a gate accepts it only if the mean score rises, some failing scenario now passes every trial, nothing that passed regresses, and no new critical failure appears.

Before and after (16 scenarios x 5 trials). Baseline: 14/80 strict passes, mean score 82.9, 29 trials with a critical failure. Final version: 60/80, mean 97.9, no critical failures. Along the way, generated policy fixes removed the made-up callbacks and the emergency handoff (S13 went from 0/5 to 5/5), and engineered code fixed duplicate bookings after a lost response (S11 0/5 to 5/5) and stopped the agent speaking appointment times it had invented. On the 4 held-out scenarios the improver never saw, strict passes rose from 5/20 to 16/20 (mean 93.0 to 98.2) and critical failures from 3 to 0. No version passed the strict regression gate: two non-critical scenarios still score below the baseline, and the README reports them.

One change for a real clinic. Make emergency escalation real: a transfer or staff-paging tool, with the agent allowed to say "connecting you" only after that tool confirms. Until then it can only direct callers to emergency services, which is the safe default but not real care coordination.

Where AI helped versus where judgment overrode it. AI built most of the harness, diagnosed each of the six applied policy fixes from raw traces, and grades the meaning of what the agent said. Judgment overrode it in five places. The judge accepted a fictitious handoff, so it now gets the ground-truth sheet. The improver first went after a minor clarity issue while 12 trials with critical callback failures waited, so selection is now severity-first. I kept the shipped model rather than a stronger or "faster" one that would make the numbers look better. Candidates with better means but some regressed scenarios stayed rejected rather than loosening the gate. And calls ending early turned out to be simulator gaps, not agent faults, so I fixed the simulator and re-ran every version, baseline included.
